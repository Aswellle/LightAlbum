# ADR-009: 导出的语义 —— 格式转换，而不是复制原件

**Status**: Accepted

## Context（背景）

- 图库是**原地索引**：扫描器只遍历用户指定的文件夹，不复制、不托管原始文件（`scanner/walker.rs`）。
- 应用**没有编辑/调整能力**：数据库里没有任何调整、裁剪、旋转的记录。
- 侧车（sharp）已能解码 HEIC 与 RAW，且已具备落盘能力（`decode` 命令的文件模式走 `sharp.toFile`）。
- 此前批处理栏里有一个长期 `disabled` 的「导出」占位（PRD M-11），点了没有反应。

## Decision（决定）

1. **不做「把原件复制到别处」的导出**：原件本来就在用户自己的文件夹里，系统资源管理器更快更顺手；这类功能只增加维护面，不增加能力。
2. **「导出」= 格式转换 / 另存**：
   - HEIC / RAW，以及任何要求改尺寸或质量的源 → 走侧车转码为 JPEG/PNG；
   - 已经满足条件的（JPEG/PNG 源 + 未指定尺寸/质量 + 格式=自动）→ `std::fs::copy` 直拷（最快且无损）。
3. **绝不覆盖**：目标目录已存在同名文件时自动改名 `name (2).jpg`、`name (3).jpg`……。
4. **单张失败不中断整批**：返回汇总 `{ exported, copied, converted, failed, failures[≤20] }`，每完成一张 emit `export:progress { done, total, current }`。
5. **定位能力单独提供**：另有一条「在资源管理器中显示」命令（Windows `explorer /select`、macOS `open -R`、Linux `xdg-open` 父目录），不把「打开位置」塞进导出流程。
6. **私密相册内允许导出**：导出是用户主动指定目标目录的操作，与「删除」同级；不做额外屏蔽（解锁状态由后端与会话决定，前端不额外发明规则）。

## Consequences

- **好**：用户心智模型清晰（导出 = 拿到一个能用的文件，而不是「把已有的文件再复制一遍」）；实现只依赖既有的侧车与文件系统，无新依赖。
- **坏**：直拷与转码两条路径让产物质量不完全一致（直拷保持原始字节，转码按用户选项）。这一点在 UI 上以「格式 / 质量 / 最长边」三项显式暴露，不隐藏。
- **可逆性**：导出是只读操作 —— 不写数据库、不进 undo 栈、不改动任何既有文件。

## Enforcement

- 侧车 smoke（`sidecar/test/smoke.js`）覆盖 `export`：产物存在、可被 sharp 重读、`maxDim` 约束生效、异常入参返回 `ok:false`。
- `ExportDialog` 在未选择目标目录时禁用「导出」；导出进行中禁止关闭对话框（后台仍在写文件，关掉会造成「已取消」的错觉）。
- 端到端：批处理栏「导出」按钮 → 对话框 → 进度 → 完成 toast（`tests/e2e/` 覆盖到按钮与对话框的存在与可用性）。
